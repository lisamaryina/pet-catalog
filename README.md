# Pet Catalog 🐾

Вебсторінка-каталог домашніх тварин, створена в межах навчального завдання.

## Можливості

- Перегляд карток тварин з фото та описом
- Пошук і фільтрація тварин
- Адаптивний дизайн для телефона та комп'ютера

## Технології

- HTML
- CSS
- JavaScript

## Як запустити

1. Клонуйте репозиторій:

## Локальний сервер (ПР №14)

Сервер на Node.js (вбудований модуль `http`) роздає сайт і JSON-API каталогу.

```bash
cd server
npm start
```

Після запуску відкрийте http://localhost:3000

| Ендпоінт | Відповідь |
|---|---|
| `GET /api/pets` | увесь каталог тварин |
| `GET /api/pets/random` | випадкова тварина |
| `GET /api/pets/:id` | одна тварина або 404 |


## Безпека (ПР №15)

Аудит клієнтської частини та локального сервера на типові вразливості (варіант 12).

### 1. XSS через `innerHTML` — поле `notes`

- **Де шукали:** усі використання `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `v-html`.
  У коді є одне — `pageContainer.innerHTML = ''` у роутері SPA. Це очищення порожнім
  рядком, даних користувача там немає, тому воно безпечне.
- **Перевірка:** у формі додано тварину з нотаткою `<img src=x onerror="alert('XSS')">`.
  `alert` не спрацював ні в картках Vue, ні на сторінці `#/pets/:id`: рядок показується
  як текст, бо нотатки виводяться через інтерполяцію Vue `{{ notes }}` (екранує HTML)
  та `document.createElement` + `textContent` (функції `renderAnimals`, `renderPetPage`).
- **Висновок:** поле `notes` до XSS не вразливе. Для випадків, коли розмітку колись
  доведеться збирати рядком, додано функцію `escapeHtml()`.

### 2. Неперевірений `photoUrl` — знайдена й усунута вразливість

- **Проблема:** адреса фото з форми потрапляла в `<img src>` без перевірки. Сторінка
  сама надсилала запит на будь-який сторонній сайт, наприклад
  `https://example.com/track.gif?owner=lisa`, — так можна стежити за користувачем.
- **Виправлення:** функція `isSafeImageUrl()` дозволяє лише зображення проєкту
  (`assets/img/*.jpg|png|gif|webp`) або адреси `https://` з розширенням зображення
  без параметрів `?…`/`#…`. Форма показує помилку для інших адрес, а вже збережені
  неперевірені адреси при рендері ігноруються (`safeImageUrl()`).
- **Обмеження перевірки:** розширення в URL не гарантує фактичний MIME-тип — сервер за
  адресою `…/cat.jpg` може повернути HTML чи будь-який інший вміст. Для `<img>` це не
  створює XSS: браузер показує лише справжні зображення і не виконує в них скриптів
  (навіть у SVG). Повну гарантію дала б перевірка заголовка `Content-Type` на сервері
  (проксі для зображень) або завантаження фото у власне сховище замість чужих посилань.
- Також обмежено довжину полів: ім'я — до 40 символів, нотатки — до 300.

### 3. localStorage / IndexedDB

- **IndexedDB `PetCatalogDB` → `pets`:** id, ім'я, вид, посилання на фото, нотатки.
  Паролів, токенів і персональних даних власника немає. Ризик — лише вільний текст
  `notes`, у який власник може сам вписати особисте (телефон, адресу), тому в
  реальному застосунку варто попередити про це в інтерфейсі.
- **localStorage:** лише прапорець `petCatalogMigrated = true`. Після міграції копія
  каталогу `petCatalogItems` видаляється, щоб не дублювати дані в незахищеному сховищі.
- **Важливо:** IndexedDB, як і localStorage, не шифрується і доступна будь-якому
  JavaScript того самого origin (`http://localhost:3000`): і нашому коду, і скрипту,
  впровадженому через XSS, і стороннім бібліотекам (наприклад, Vue з CDN unpkg).
  Тому захист від XSS одночасно захищає й дані у сховищах, а для реального застосунку
  варто фіксувати точну версію бібліотек із CDN і додавати атрибут `integrity` (SRI).

### 4. Секрети

Пошук за `key`, `token`, `secret`, `password` нічого не знайшов. Зовнішніх API з ключами
немає: Dog CEO API з ПР №9 замінено власним сервером, якому ключ не потрібен.

### 5. Сервер і HTTPS

- Сервер додає заголовок `X-Content-Type-Options: nosniff` до всіх відповідей.
- Під час розробки сайт працює на `http://localhost:3000` — браузер вважає localhost
  безпечним контекстом, тому HTTPS тут не потрібен.
- **Розгортання:** GitHub Pages віддає лише статичні файли й не запустить Node-сервер,
  тому для фінальної здачі обрано **Render** (Web Service: `cd server && npm start`).
  Render видає HTTPS-сертифікат автоматично, а сервер уже читає порт із `process.env.PORT`.
